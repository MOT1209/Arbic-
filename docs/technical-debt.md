## 2. تفصيل البنود

### TD-01 — ملفات اعتماد في جذر المستودع (P0)

**الدليل:** `git status` يُظهر 7 ملفات غير متتبعة:

```text
cmdkey_all.txt    5,748 bytes
gh_code.txt       0
gh_code_err.txt   189
gh_login.txt      0
gh_login_err.txt  211
push_err.txt      166
push_log.txt      0
```

`.gitignore` لا يستثني أيًا منها.

**الأثر:** أي `git add .` قد يرفع أسرارًا (مفاتيح/توكنات) إلى التاريخ العام. حتى لو كانت الملفات فارغة، أسماء مثل `cmdkey_all` تدل على محاولات مصادقة.

**المعالجة المقترحة (Phase 1):**
1. فحص الملفات يدويًا وتحديد ما إذا كانت تحتوي أسرارًا.
2. إن كانت تحتوي: إبطال/تدوير المفاتيح فورًا.
3. حذفها من شجرة العمل، وإضافة أنماط مثل `*.txt` المؤقتة أو أسماء محددة إلى `.gitignore`.
4. فحص التاريخ (`git log -p --all -- '*.txt'`) للتأكد من عدم تسريبها سابقًا.
5. إضافة `SECURITY.md` يوضح سياسة الإبلاغ.

**لا يُنفَّذ حذف تلقائي في Phase 0** لأن المحتويات لم تُفحص وقد تكون مطلوبة للمستخدم.

### TD-02 — عقد أكواد الأخطاء غير مطابق (P1)

**الدليل:** `al_arabiya/compiler/diagnostics/errors.py` هو المصدر الفعلي:

| E1001 | UNEXPECTED_CHARACTER |
| E1002 | UNTERMINATED_STRING |
| E1003 | INVALID_ESCAPE |
| E1004 | INVALID_NUMBER |
| E1005 | UNEXPECTED_OPERATOR |
| E2001 | EXPECTED_TOKEN |
| E2002 | UNEXPECTED_TOKEN |
| E2003 | UNEXPECTED_EOF |
| E2004 | MISSING_BLOCK_END |
| E2005 | EXPECTED_IDENTIFIER |
| E2006 | EXPECTED_NEWLINE |
| W3001 | IMPLICIT_DECLARATION |
| E4001 | UNDEFINED_VARIABLE |
| E4002 | DIVISION_BY_ZERO |
| E4003 | TYPE_ERROR |

**الأثر:** أي أداة (LSP، docs، اختبارات خارجية) تعتمد على كتالوج خاطئ.

**المعالجة:** توثيق الجدول من `errors.py`، وإضافة اختبار يتحقق من تطابق كل عضو `ErrorCode` مع صف في المواصفات (مصدر حقيقة واحد).

### TD-03 — توثيق يصف سلوكًا غير موجود (P1)

**الدليل (تشغيل فعلي):**

| الادعاء | النتيجة |
|---|---|
| التعبير يمتد عبر أسطر داخل `( )` | `اطبع (1 +` + `2)` → E2002 |
| `شي` = `None` | E4001 «المتغير 'شي' مش معرّف» |
| `و`/`أو` تُرجع قيمة كبايثون | تُرجع `bool` دائمًا |

**الأثر:** أعلى خطر على أي وكيل لاحق: يبني على مواصفة كاذبة.

**المعالجة:** إما تنفيذ السلوك أو تصحيح التوثيق — مع اختبار لكل ادعاء. التوصية: تصحيح التوثيق في Phase 1، وتنفيذ multi-line في Phase 2 (لأنه يحتاج قاعدة NEWLINE داخل الأقواس).

**الحالة: ✅ اتصلح في Phase 1** (تصحيح التوثيق فقط). التعبير متعدد الأسطر لسه غير مدعوم ومؤجَّل لـ Phase 2.

**الدليل:** لا `.github/`؛ `tools/check.py` محلي فقط.

**المعالجة:** GitHub Actions على Python 3.12 و3.13: `ruff check .`، `mypy`، `pytest`. إضافة حماية فرع main. (Phase 1)

**الحالة: ✅ اتصلح في Phase 1** — `.github/workflows/ci.yml` بيشغّل الفحوص الثلاثة + فحص الأمثلة، على Python 3.12/3.13/3.14 وUbuntu/Windows. حماية فرع `main` إعداد على GitHub نفسه ولسه محتاجة تفعيل يدوي.

### TD-05 — هوية وروابط قديمة ونص تالف (P1)

**الدليل (وقت التدقيق):**
- `README.md:30` و`pyproject.toml:26`: `https://github.com/ahmedfox1/masry`.
- `README.md` كان بيحتوي «ب逃脱ات» (أحرف CJK) وثلاثة أسطر `"# Arbic-"` بعد `</div>` — اتصلحوا في Phase 1 وبعد الدمج.
- `docs/development/guide.md` يذكر `compiler/positions.py` (الفعلي `compiler/lexer/positions.py`) و`token_kind_of` (غير موجود) و`tools/gen_goldens.py` (غير موجود).
- `docs/architecture/phase-1-analysis.md` §4.5 يذكر exit code `3` غير موجود.

**المعالجة:** جرد روابط/مسارات، تصحيحها، وإضافة فحص Markdown links في CI. توحيد الهوية وفق ADR-01.

**الحالة: 🟡 جزئي في Phase 1** — الرابط اتصلح في README و`pyproject.toml`، والنص التالف والأسطر الزائدة اتشالوا، ومسارات `guide.md` وأكواد الخروج في `phase-1-analysis.md` اتصحّحوا. توحيد الاسم (Arbic ⚖️ AlArabiya) لسه محتاج ADR-01، وفحص الروابط في CI لسه مش موجود.

### TD-06 — لا دوال (P1)

**الدليل:** لا `TokenType.KW_FUNCTION`، لا `CallExpression`، لا `ReturnStatement`، لا `Environment.child()` مستخدمة. `environment.py` يوثّق أن السلسلة «جاهزة للدوال لاحقًا».

**الأثر:** يمنع OOP، Stdlib، IR ذا معنى، VM calls، LSP signature help، interop.

**المعالجة (Phase 2):** عقدة `FunctionDeclaration`، `CallExpression`، `ReturnStatement`، إطار استدعاء، نطاق محلي، أخطاء arity/نوع، ثم اختبارات + توثيق.

---

### TD-07 — لا مجموعات بيانات (P1)

**الدليل:** الرموز `[ ] { } , :` تُlex فقط؛ لا parser ولا AST ولا `Value` يدعمها.

**المعالجة (Phase 2):** `قائمة`، `قاموس`، فهرسة، شرائح (اختياري)، تكرار `لكل` لاحقًا، مع دلالات مرجعية مقابل قيمة موثّقة.

---

### TD-08 — لا وحدات (P2)

**الدليل:** لا `استورد`، وCLI يقرأ ملفًا واحدًا.

**المعالجة (Phase 2/3):** resolver للمسارات، منع path traversal، دورة استيراد، أسماء مؤهلة.

---

### TD-09 — لا تحليل دلالي/أنواع (P2)

**الدليل:** لا `semantic/` ولا `type_checker/`. كل التحقق نوعي وقت التشغيل (`E4003`).

**الأثر:** لا يمكن كشف `خلي س = "نص"` ثم `س / 2` قبل التشغيل، ولا دعم annotations.

**المعالجة (Phase 4):** symbol table + scopes + module-aware analysis + gradual typing + strict mode.

---

### TD-10 — `كرر` يقبل قيمًا غير صالحة بصمت (P2)

**الدليل (تشغيل فعلي):**

```text
كرر -2 مرات   → لا يطبع شيئًا، exit 0
كرر 2.9 مرات  → يطبع مرتين، exit 0
```

الكود: `range(int(count))` بلا تحقق من `count >= 0` أو الجزء الكسري. `E4004` يُستخدم فقط عندما تكون القيمة غير رقمية.

**المعالجة:** قرار دلالي (خطأ أم تقريب؟) + تشخيص `E4004` موسّع + اختبارات سالبة + توثيق.

---

### TD-11 — REPL heuristic (P2)

**الدليل:** `repl.py` يبني الاستمرارية من `_bracket_delta` + `_is_incomplete` (خطأ يبدأ عند `offset >= len(source)`). لا اختبار لنِسَب متداخلة أو نص غير مغلق متعدد الأسطر.

**الأثر:** قد يعلّق الإدخال أو ينفّذ كتلة ناقصة في حالات حدّية.

**المعالجة:** تحويل التجميع إلى lexer-aware block-depth (عدّ `لو/كرر/طالما` و`خلاص`) + اختبارات حدّية.

---

### TD-12 — نطاق عالمي واحد (P2)

**الدليل:** `Interpreter` لا يستدعي `Environment.child()`؛ التوثيق يقرّ بذلك في `phase-1-analysis.md` §4.4.

**الأثر:** `خلي` داخل `لو` يبقى بعد `خلاص`. هذا سلوك legacy مقصود، لكنه سيصبح مربكًا مع الدوال/الكتل.

**المعالجة:** ADR-02 قبل Phase 2، مع سياسة توافق: إبقاء السلوك للبرامج القديمة أو إعلان كسر موثّق.

---

### TD-13 — لا package manager (P1 عند بنائه)

**الدليل:** لا مجلد `packages/` ولا أوامر `install`. لذلك بند الماستر برومبت «إصلاح ثغرات مدير الحزم» لا ينطبق حاليًا؛ لا يوجد كود لإصلاحه.

**المعالجة (Phase 8):** بناء من الصفر باستخراج آمن (رفض `..`، المسارات المطلقة، symlink escapes)، checksums، lockfile، resolver بالتراجع، وسياسة تشغيل سكربتات صريحة.

---

### TD-14 — لا اختبارات خصومية (P2)

**الدليل:** لا `tests/security/`، لا Hypothesis، لا fuzz. أقصى ما يوجد: `test_invalid_number_reports_error` وحالات أخطاء يدوية.

**المعالجة:** fuzz للـ lexer/parser، property tests للـ round-trip، security tests للاستيراد والحزم، في Phase 1 وPhase 10.

---

### TD-15 — لا benchmarks (P3)

**الدليل:** لا `tests/benchmarks/`. أي ادعاء تحسين أداء لاحقًا سيكون بلا دليل.

**المعالجة:** harness بسيط: زمن بدء، زمن ترجمة، زمن تنفيذ برامج مرجعية، ذاكرة. يُشغَّل في CI (غير حاجز) ويسجل الأرقام.

---

### TD-16 — ازدواجية صغيرة في CLI (P3)

**الدليل:** `cli/main.py` يقرأ الملف يدويًا رغم وجود `SourceFile.from_path`. و`_emit_diagnostics(diagnostics: object)` مع `# type: ignore[arg-type]` — أي أن بوابة mypy الصارمة بها استثناء.

**المعالجة:** تمرير `Sequence[Diagnostic]` وحذف ignore، واستخدام `SourceFile` كمصدر وحيد للقراءة.

---

### TD-17 — `span` الأقواس (P3)

**الدليل:** `_parse_prefix` عند `LPAREN` يرجع العقدة الداخلية بلا توسيع `span` ليشمل `)`.

**الأثر:** تشخيصات/تظليل LSP يشير إلى نطاق أضيق من المصدر.

**المعالجة:** عقدة `GroupingExpression` أو توسيع span مع الحفاظ على الموضع الداخلي.

---

### TD-18 — مستندات المشروع الناقصة (P2)

**الدليل:** لا `CONTRIBUTING.md`، لا `SECURITY.md`، لا `docs/migration-2.0.md`، لا `docs/language-specification.md`.

**المعالجة:** Phase 1 للسياسات، Phase 2 للمواصفة الرسمية.

---

### TD-19 — أوامر CLI الناقصة (P2)

**الدليل:** `_COMMANDS = {"run", "check", "repl", "version", "help"}`.

**المعالجة:** `init`/`build`/`test`/`format` تحتاج مشروعًا وformatter وtest runner — أي Phase 8/9.

---

### TD-20 — لا نموذج عزل موثّق (P1 قبل التنفيذ)

**الدليل:** لا interop ولا playground. الماستر برومبت يشترط ألا يُنفَّذ كود غير موثوق داخل نفس العملية.

**المعالجة:** تصميم عزل (subprocess/container + resource limits + filesystem/network restrictions) قبل كتابة أول سطر interop. لا يُنفَّذ allowlist فقط كضمان أمني.

---

### TD-21 — سياسة الإصدارات (P3)

**الدليل:** `__version__ = "0.1.0"` و`pyproject` 0.1.0، بينما الهدف المعلن «Arbic 2.0».

**المعالجة:** ADR-01 + سياسة SemVer: هل 2.0 تعني كسر توافق 0.1 أم إعادة تسمية؟ لا تُرقَّم إصدارات قبل حسم ذلك.
